## 1. 项目概览

这是一个以“摄影师 / 剪辑师”身份为核心的个人作品集网站，面向求职与商业合作展示。网站以暗色与红色 `#FF3B2F` 为主视觉，融合全屏视频、照片墙、作品卡片、展厅式影片播放、优势卡片与故障文字收尾，强调“电影感 + 技术感”。

页面结构：

1. **首屏 Hero**：全屏背景视频、主标题“让每一帧，都有它的理由。”、身份标签、作品集状态、滚动提示
2. **关于 About**：个人介绍、证件照 / 生活照照片墙、教育经历、工作经历、联系方式
3. **作品 Works**：5 个项目卡片，含 1 个精选项目、1 个五展项展厅、其他商业 / 个人短片
4. **优势 Capabilities**：6 张能力卡片 + 4 个数据卡
5. **联系 Contact**：大标题“无限进步”、GlitchText 故障文字、邮箱、电话、所在地、求职状态

## 2. 技术栈

| 层级 | 技术 |
|---|---|
| 框架 | React 19 + TypeScript |
| 构建 | Vite 7 |

| 部署 | Vite 静态构建，产物 `dist`，可部署到任意静态托管 / CDN |

## 3. 关键实现

### 3.1 视觉与动效

- **开场**：品牌幕布 + 首屏标题逐行揭幕，使用 GSAP 时间线控制节奏。
- **滚动叙事**：ScrollTrigger 驱动区块标题、卡片、图片的入场与视差；卡片错峰出现。
- **WebGL 背景**：GhostFibers 以固定画布铺在首屏以下，红色双色光纤 + 景深 + 泛光；首屏阶段暂停，滚动后启动。
- **GlitchText**：作品区标题与收尾页“无限进步”使用切片错位 + 红/青阴影，约 4.2 秒循环；离屏时暂停动画。
- **BorderGlow**：优势卡片与数据卡边缘跟随鼠标产生红色辉光。
- **项目弹窗**：Portal 渲染，支持 Esc 关闭、← → 切换、背景锁定、焦点管理；展厅支持 5 个展项切换与站内视频播放。
- **减少动态**：`prefers-reduced-motion` 下关闭开场、视频自动播放与 WebGL，保留静态内容。

### 3.2 性能处理

- 首屏视频延迟 1 秒挂载，先显示封面；避免与字体、JS、封面抢带宽。
- WebGL 在首次滚动或空闲后初始化，DPR 上限 1.5；首屏、联系页、项目弹窗打开时暂停渲染。
- 图片与项目视频懒加载；关于区照片、项目封面、联系页背景均按需加载。
- GlitchText 离屏暂停；滚动监听使用 `requestAnimationFrame` + passive；导航高亮用 IntersectionObserver。
- 当前构建体积：主 JS 约 **134KB gzip**，CSS 约 **12.6KB gzip**，GhostFibers 独立 chunk 约 **9.6KB gzip**。
- 视频规格：奥太娜线上版约 **99.46MB / 960×540**；另有 **908MB / 1920×1080 / 4.4Mbps** 高清母版，可按托管能力替换。

## 5. 本地运行与构建

环境要求：

- Node.js 22+
- pnpm 11（仓库建议在 `package.json` 声明 `"packageManager": "pnpm@11.28.5"`）

```bash
pnpm install
pnpm dev        # 本地预览 http://127.0.0.1:5173/
pnpm build      # 生成 dist/
pnpm preview    # 预览构建产物 http://127.0.0.1:4173/
```

注意：

- `pnpm install` 可能出现 `ERR_PNPM_IGNORED_BUILDS: esbuild`。`pnpm-workspace.yaml` 已声明 `onlyBuiltDependencies: esbuild`；如仍出现，执行 `pnpm approve-builds` 允许 esbuild。
- 构建前确保 `.vite/` 已加入 `.gitignore`，避免缓存进入仓库。

## 6. 内容维护

全站内容集中在 `src/data/content.ts`，主要字段：

- `profile`：姓名、身份、电话、邮箱、所在地、求职状态、个人介绍
- `projects`：项目标题、英文名、年份、类别、封面、摘要、角色、影片、海报、展厅数组
- `strengths`：6 张能力卡
- `stats`：4 个数据卡
- `contact`：收尾页文案、邮箱、电话、所在地、开放地点

替换项目时：

1. 将封面 / 海报放入 `public/images/`，建议 WebP、16:9 或 4:5。
2. 将视频放入 `public/video/`，H.264 MP4、`faststart`，文件名与 `content.ts` 中 `video` 字段一致。
3. 修改 `content.ts` 对应项目；展厅项目修改 `gallery` 数组。
4. 如视频超过托管限制，先压缩或改为外链；上线前确认首帧海报与视频时长一致。

## 8. 部署说明

网站是纯静态站点，构建产物为 `dist/`，不需要服务端。

上线流程：

1. `pnpm build`
2. 将 `dist/` 上传到静态托管 / CDN，或由托管平台连接源码仓库自动构建
3. 绑定域名并开启 HTTPS
4. 配置缓存：`assets/*` 长缓存，`index.html` 短缓存
5. 确认视频可 Range 请求（拖动进度条）

路径要求：

- 站点部署在**根路径**时，现有 `/images`、`/video` 可直接使用。
- 如部署在子路径（如 `/portfolio/`），需要同步调整 Vite `base` 与资源路径，否则图片 / 视频会 404。

视频与大文件：

- 若托管单文件限制低于视频体积，需将大视频放到对象存储 / Release / 视频平台，页面通过外链读取。
- 当前线上版使用 99.46MB 的 960×540 奥太娜；908MB 1080p 母版建议单独存放，不放入静态站点。

## 10. 已知限制

- 微信视频号内容无法直接嵌入站内播放，只能外链；预览页只提供封面，不提供视频流。
- 908MB 的 1080p 奥太娜超出多数静态托管的单文件限制，线上默认使用 99.46MB 版本；高清母版需另存。
- 首屏视频来自 B 站渲染大赛集锦，公开商用前需替换为自有授权素材。
- 站点无后端，联系表单未接入；当前通过邮箱 / 电话联系。

## 12. 维护建议

- 每次替换项目后，重新生成封面 / 海报，压缩到目标体积。
- 视频统一 H.264 + `faststart`，避免首帧黑屏。
- 修改 `content.ts` 后执行 `pnpm build`，确认无 TypeScript 报错。
- 保留 `.media/` 下的 1080p 母版，不要提交到源码仓库。
- 定期检查外链（视频号、字体、封面）是否失效。
